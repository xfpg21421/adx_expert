# 00_研究方法与协作规范

> **本目录用途**：定义"怎么研究、怎么提问、怎么记录"。是项目的元层（meta layer），
> 所有其他目录的产出都遵循这里的规范。新对话开始时，助手应先读本目录的 `协作规则.md`。

---

## 文档清单

- [x] `协作规则.md` —— 协作契约：角色分工、五条硬性输出规则、内容深度约定、响应模板映射、灰色地带红线、落盘流程、默认前提
- [x] `提问模板.md` —— 7 种提问模板（A 概念 / B 现象 / C 日志 / D 案例 / E 对比 / F 专题 / G 复盘）+ 快速触发词表
- [x] `术语卡片模板.md` —— 术语精简版（表格行）/ 完整版（12 段）/ 易混对照卡；含 16 组高频混淆清单
- [x] `案例拆解模板.md` —— 4 类模板：商业案例 / 业务现象诊断 / 竞品拆解 / 日志分析
- [x] `研究进度看板.md` —— 阶段进度、已完成文档、待研究问题池、认知更新日志、失效复核清单

## 快速上手

| 我想… | 打开 |
|---|---|
| 知道助手该怎么回答我 | `协作规则.md` §二（五条硬性规则） |
| 提一个高质量的问题 | `提问模板.md`，挑 A~G 之一填空 |
| 沉淀一个新术语 | `术语卡片模板.md` §一或§二 → 写入 `02_核心术语与知识库/` |
| 拆解一个案例/异动 | `案例拆解模板.md` → 写入 `15_案例与实战复盘/` |
| 看整体进度 | `研究进度看板.md` |
| 改协作规则 | 直接改 `协作规则.md`，并在其 §八变更记录追加一行 |

## 写作要点

- 本目录文件是**规范**，不是知识，不要往里塞业务内容。
- 规则要可执行、可判定，避免"尽量""适当"这类模糊表述。
- 每次规则调整都要留变更记录，方便回溯为什么当初这么定。
