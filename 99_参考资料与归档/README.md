# 99_参考资料与归档

> **本目录用途**：**支撑层**。存放外部资料的指针、行业报告与数据来源说明、标准协议文档索引，
> 以及全项目的图片附件与过期内容归档。

**在全局中的位置**：所有目录的公共依赖。正文文档不直接抄外部内容，而是**指向这里登记的来源**；
本目录不产生观点，只保证"每条结论都能被追溯到一个可核对的出处"。

## 写作要点

- **只存指针与要点摘录，不搬运大段原文**——既是版权问题，也是时效问题（外部文档会改版，副本会立刻过期）。
  摘录控制在 1~3 句，够说明"这份资料能回答什么问题"即可。
- **每条链接必须注明访问日期与内容摘要**，统一格式：

```
- [OpenRTB 2.6 Specification](https://iabtechlab.com/...)
  访问日期：2026-09-08 ｜ 类型：标准规范 ｜ 语言：EN
  摘要：BidRequest / Imp / BidResponse 核心对象定义，2.6 相对 2.5 的变化在附录。
  用于：05/OpenRTB协议详解.md、05/ADX交易链路与RTB时序.md
  状态：有效（IAB Tech Lab 维护中）
```

- **过期文档移入 `归档/`，不直接删除**：原位置留一行指引（`> 本文档已于 YYYY-MM-DD 归档，见 ../99_参考资料与归档/归档/xxx.md，原因：…`），
  归档文件头部注明失效原因与被谁取代。删除会切断已有正文里的引用链。
- **区分来源等级**并在条目上标明：官方标准 / 官方文档 > 监管与行业组织报告 > 头部厂商技术博客 > 第三方研究 > 个人博客与论坛。
  低等级来源的结论在正文中必须标 `[来源较弱]`。
- 数据类来源额外记口径：统计范围（全球 / 中国 / 分国家）、是否含电商站内广告、货币与汇率基准、发布频率、是否付费墙。
  同一指标不同报告能差数倍，口径不记等于没记。
- 图片与附件命名 `YYYYMMDD_主题_序号.png`，避免 `image1.png`；大文件（>5MB）只留链接不落盘。
