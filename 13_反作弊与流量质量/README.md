# 13_反作弊与流量质量

> **本目录用途**：**防守方视角**研究广告欺诈。理解作弊原理是理解整个广告系统脆弱性的最快路径，
> 也是做变现、投放、联盟时避免被割的必要知识。覆盖欺诈分类、IVT 标准口径、检测特征、防御体系与第三方验证。

> ⚠️ **红线声明**：本目录立场是**认知与防守**，只研究「原理 / 特征 / 检测 / 防御」四件事——
> **不写如何实施作弊，不推荐任何工具、参数、流量源或规避审核技巧**。
> 判定标准一句话：**输出内容如果被作弊方直接拿去执行，就是越线**。
> 所有作弊手法的描述到"能被检测出什么特征"这一层即止，到此打住。

**在全局中的位置**：横向贯穿层。`05` 的交易链路、`07` 的归因口径、`09` 的联盟结算、`11`/`12` 的买卖两侧，
每一环都有对应的欺诈形态；本目录提供统一的分类框架与判定标准，被其他目录反向引用。

## 写作要点

- **统一写作范式：三列表格**。每种手法只允许写到"特征"与"防御"，第三列之后不再展开：

| 作弊手法 | 可检测特征 | 防御手段 |
|---|---|---|
| Click Injection | CTIT 分布异常（点击到安装时间极短且高度集中） | MMP 侧 CTIT 阈值与分布校验、Google Install Referrer 校验 |
| SDK Spoofing | 请求参数组合不可能出现、签名缺失或重放 | MMP 签名验证（signed request）、时间戳与 nonce 防重放 |
| Device Farm / Bot | IP 段与 ASN 集中、设备指纹一致性过高、行为序列过于规整 | 名单体系 + 无监督异常检测 + 图算法识别团伙 |
| Cookie Stuffing / 归因抢占 | 点击无对应曝光、转化前点击密度异常 | 要求点击-曝光配对、Last Click 之外叠加多触点校验 |

- **口径先行**：谈"作弊率"必须先说清分母（过滤前 or 过滤后）、判定方（自研 / MMP / 第三方验证）与是否经 MRC 认证，
  否则同一批流量能得出差好几倍的数字。
- 防御方案要写**成本与误杀率**：规则引擎的覆盖率、模型打分的延迟预算、名单体系的维护成本、申诉通道设计。
  只讲"能识别"不讲"误杀多少正常用户"的防御方案是不完整的。
- 强调**对抗的动态性**：任何检测特征都有半衰期，写作时标注该特征的"当前有效性"，并列入 `研究进度看板.md` 失效复核清单。
- 涉及 MRC 标准、平台政策（Google Invalid Traffic 政策、Meta 的 IVT 扣除）标 `[政策]` + 版本与时点。
