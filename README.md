## 一、项目简介

### 1.1 这个项目解决什么问题

互联网广告是一个**业务黑话密集、链路极长、国内外差异巨大**的领域。同一名词（如 "联盟"、"归因"、"eCPM"）
在广告主、媒体、平台、Affiliate 玩家、套利玩家的嘴里含义完全不同。碎片化搜索得到的答案往往：

- 只讲结论不讲链路（知道 oCPM 但不知道它背后是怎么算出价的）；
- 只讲国内不讲海外（不知道 Prebid / TCF / SKAN 这些海外基础设施）；
- 只讲技术不讲钱（不知道一个技术设计对应的是哪一段分成和毛利）；
- 灰色地带语焉不详（Arbitrage、MFA 站、点击注入几乎搜不到系统性材料）。

本项目的目标：**把上述四类知识按统一框架整理成结构化文档，形成可复用的心智模型与速查手册。**

### 1.2 研究立场

- **原理优先**：任何现象先问"链路上哪一环、谁付钱、谁赚钱、数据怎么流"。
- **四层拆解**：每个问题都区分 **业务层 / 产品层 / 技术层 / 商业化层**（见 §四）。
- **国内外对照**：默认给出海外主流做法 + 国内差异，避免单一市场视角。
- **中英对照**：所有专业术语必须给出英文原文，因为一手资料（IAB 标准、平台文档、财报）都是英文。
- **可验证**：涉及数字、比例、平台政策时标注来源与时间，过期结论要标注"已失效"。

### 1.3 不做什么

- 不写投放代操盘的实操脚本、不做真实资金投放；
- 不提供规避平台风控 / 绕过反作弊 / 制造无效流量的具体操作方法（**只从防守方视角研究作弊原理**）；
- 不替代平台官方文档，本项目是"理解框架"，具体参数以平台当期文档为准。

## 四、四层分析框架（回答任何广告问题的默认结构）

> **这是本项目最核心的思维约定。** 收到任何广告相关问题，先判断落在哪一层，再分层作答。

| 层 | 关注问题 | 典型关键词 |
|---|---|---|
| **① 业务层 Business** | 谁付钱、谁赚钱、解决什么商业诉求、上下游关系、行业惯例 | 广告主、代理、媒体、预算、分成、Take Rate、KPI |
| **② 产品层 Product** | 用户/客户看到什么形态、交互与体验、产品规则与约束、漏斗设计 | 广告样式、素材、落地页、账户结构、定向选项、审核规则 |
| **③ 技术层 Technical** | 系统怎么实现、数据怎么流、时延与协议、模型与算法、埋点与追踪 | OpenRTB、召回排序、CTR/CVR、出价引擎、SDK、Postback、归因 |
| **④ 商业化层 Monetization** | 怎么计价、怎么算收益、指标口径、优化杠杆、风险与合规 | CPM/eCPM/ROAS/ARPU、Waterfall、Header Bidding、IVT、GDPR |

**输出格式约定**：

```
【问题定位】业务层 / 产品层 / 技术层 / 商业化层（可多层）
【一句话结论】
【分层拆解】① 业务层 → ② 产品层 → ③ 技术层 → ④ 商业化层
【关键术语】术语 = 定义 + English + 通俗解释
【国内 vs 海外】差异点（如适用）
【延伸追问】3 个值得继续挖的问题
【可保存为】建议落盘路径，如 05_技术架构与系统实现/智能出价Bidding策略.md
```

## 五、关键术语索引（速查）

> 完整分类术语表见 [`02_核心术语与知识库/`](./02_核心术语与知识库/)。
> 本表只收录"高频 + 易混 + 必须先懂"的 60 个。

### 5.1 角色与平台

| 术语 | English | 通俗解释 |
|---|---|---|
| 广告主 | Advertiser | 出钱买曝光/转化的一方（品牌、电商、App、游戏） |
| 代理商 | Agency / Ad Agency | 代广告主操盘投放，赚服务费或返点 |
| DSP | Demand-Side Platform，需求方平台 | 帮**买方**在多个 ADX 上自动竞价买流量的系统 |
| SSP | Supply-Side Platform，供给方平台 | 帮**卖方**（媒体）把广告位卖出去、卖得更贵的系统 |
| ADX | Ad Exchange，广告交易平台 | 撮合买卖双方的实时竞价市场，本质是"股票交易所" |
| Ad Network | 广告网络 / 广告联盟 | 把中小媒体流量打包，转卖给广告主的中间商（比 ADX 更早、更黑盒） |
| DMP | Data Management Platform，数据管理平台 | 存人群标签、做定向和 Lookalike 的数据仓库 |
| MMP | Mobile Measurement Partner，移动归因平台 | AppsFlyer / Adjust / Kochava，判定 App 安装该算给谁 |
| Affiliate Network | 联盟网络 | CJ、Impact、ShareASale、Awin，撮合广告主与推广者 |
| Publisher | 发布者 / 媒体 | 拥有流量的一方（网站、App、博主） |
| Retail Media | 零售媒体 | 电商平台把自己的站内流量卖给品牌方（Amazon Ads / 阿里妈妈） |

### 5.2 交易与计费

| 术语 | English | 通俗解释 |
|---|---|---|
| CPM | Cost Per Mille | 每千次曝光成本，品牌广告主最常用的计价单位 |
| CPC | Cost Per Click | 每次点击付费，效果广告的起点 |
| CPA | Cost Per Action | 每次有效动作（注册/下载/下单）付费 |
| CPS | Cost Per Sale | 按成交金额分成，Affiliate 电商最常用 |
| CPL | Cost Per Lead | 每条销售线索付费，金融/教育/保险常用 |
| CPI | Cost Per Install | 每次 App 安装付费 |
| oCPM / oCPC / oCPX | Optimized CPM/CPC/X | **按曝光/点击计费，但系统按转化目标自动优化出价**（国内主流） |
| RTB | Real-Time Bidding，实时竞价 | 一次曝光在 ~100ms 内完成拍卖的机制 |
| PMP | Private Marketplace，私有交易市场 | 邀请制的 RTB，优质媒体只对指定买方开放 |
| Programmatic Guaranteed | 程序化保量 | 用程序化管道执行传统的保量保价合约 |
| Take Rate | 抽成率 / 平台分成比例 | 平台从流水中抽走的比例（如 AdSense 历史上把约 68% 收入分给站长） |
| Floor Price | 底价 | 卖方设定的最低成交价 |
| GSP | Generalized Second Price，广义第二价格拍卖 | 搜索广告经典机制：赢家付第二名的价 + 0.01 |
| VCG | Vickrey-Clarke-Groves | 理论最优拍卖机制，激励说真话，工程上少用 |

### 5.3 效果指标

| 术语 | English | 通俗解释 |
|---|---|---|
| Impression | 曝光 | 广告被展示一次（口径争议极大：加载 vs 可见 vs 验证） |
| CTR | Click-Through Rate，点击率 | 点击 / 曝光，衡量素材与人群匹配度 |
| CVR | Conversion Rate，转化率 | 转化 / 点击，衡量落地页与产品承接能力 |
| eCPM | Effective CPM，千次展示有效收入 | **卖方视角**的收入指标 = 收入 / 曝光 × 1000 |
| Fill Rate | 填充率 | 有广告可展示的次数 / 广告请求次数 |
| Show Rate | 展示率 | 实际展示 / 填充返回，反映前端渲染与用户行为损耗 |
| ROAS | Return On Ad Spend，广告支出回报率 | 广告带来的收入 / 广告花费，电商与游戏核心指标 |
| LTV | Lifetime Value，用户生命周期价值 | 一个用户在整个生命周期贡献的毛利 |
| ARPU / ARPPU | Average Revenue Per (Paying) User | 每用户 / 每付费用户平均收入 |
| K-Factor | 病毒系数 | 一个用户带来的新用户数 |
| CAC | Customer Acquisition Cost | 获客成本 |
| Payback Period | 回本周期 | 花掉的获客成本多久被 LTV 覆盖 |
| Viewability | 可见性 | 曝光是否真被人看到（IAB 标准：≥50% 像素在屏 ≥1 秒） |
| IVT | Invalid Traffic，无效流量 | 机器/作弊流量，分 GIVT（可过滤）与 SIVT（需高级判定） |

### 5.4 技术栈与协议

| 术语 | English | 通俗解释 |
|---|---|---|
| OpenRTB | Open Real-Time Bidding | IAB Tech Lab 的 RTB 通信协议标准，行业通用语言 |
| VAST / VMAP / VPAID | Video Ad Serving Template 等 | 视频广告投放/插播点位/交互的标准协议 |
| MRAID | Mobile Rich Media Ad Interface Definitions | 移动富媒体广告与 App 交互的标准接口 |
| Prebid.js | — | 开源的 Header Bidding 客户端库，事实标准 |
| Header Bidding | 头部竞价 | 媒体在调 Ad Server 之前先让多家 SSP 竞价，提升收益 |
| Ad Server | 广告服务器 | 决定"最终展示哪个广告"的系统（如 Google Ad Manager） |
| Creative | 创意 / 素材 | 广告的实际内容（图/视频/HTML5） |
| Landing Page | 落地页 | 点击后到达的页面，转化发生的地方 |
| Tracking Pixel | 追踪像素 | 1×1 图片埋点，用于记录曝光/转化 |
| Postback / S2S | 服务端回传 | 服务器到服务器的转化通知，比客户端埋点更可靠 |
| SDK | Software Development Kit | App 内嵌的广告/归因/统计代码包 |
| Bid Request / Bid Response | 竞价请求 / 响应 | RTB 中 SSP→DSP 的询价与 DSP→SSP 的报价 |
| QPS | Queries Per Second | 广告系统核心容量指标，头部 ADX 达百万级 |
| Timeout | 超时 | DSP 未在时限内响应即弃权，通常 100~120ms |

### 5.5 身份、追踪与隐私

| 术语 | English | 通俗解释 |
|---|---|---|
| First-party Cookie | 第一方 Cookie | 用户访问的网站自己种的，仍然合法可用 |
| Third-party Cookie | 第三方 Cookie | 跨站追踪的核心载体，正在被浏览器淘汰 |
| IDFA / GAID | Identifier for Advertisers / Google Advertising ID | iOS / Android 广告标识符，需用户授权 |
| CAID | China Advertising ID | 国内 iOS 无 IDFA 时代的替代方案（中国广告协会） |
| OAID | Open Anonymous Device Identifier | 国内 Android 移动安全联盟推的匿名标识 |
| Device Fingerprint | 设备指纹 | 通过多维特征推断设备身份，隐私合规下受限 |
| GDPR | General Data Protection Regulation | 欧盟通用数据保护条例，2018 生效，罚款最高全球营收 4% |
| CCPA / CPRA | California Consumer Privacy Act | 加州消费者隐私法，美国最严州法 |
| TCF | Transparency & Consent Framework | IAB Europe 的合规授权框架，CMP 弹出的同意弹窗走的就是这套标准 |
| CMP | Consent Management Platform | 同意管理平台，负责弹窗、记录、下发授权字符串 |
| SKAN / SKAdNetwork | StoreKit Ad Network | Apple 的隐私归因方案，聚合、延迟、无用户级数据 |
| Privacy Sandbox | — | Google 的无 Cookie 替代方案集合（Topics、Protected Audience 等） |
| 个保法 | 个人信息保护法（PIPL） | 中国 2021 生效，对标 GDPR |

### 5.6 归因模型

| 术语 | English | 通俗解释 |
|---|---|---|
| Last Click | 最后点击归因 | 功劳全给最后一次点击，最常用也最偏颇 |
| First Click | 首次点击归因 | 功劳全给第一次接触 |
| Linear | 线性归因 | 所有触点平分功劳 |
| Time Decay | 时间衰减归因 | 越靠近转化的触点权重越高 |
| Position-Based / U-Shape | 位置归因 / U 型 | 首尾各 40%，中间 20% |
| Data-Driven Attribution | 数据驱动归因（DDA） | 用 Shapley Value / 机器学习算各触点边际贡献 |
| MTA | Multi-Touch Attribution，多触点归因 | 用户级路径归因的统称 |
| MMM | Marketing Mix Modeling，营销组合模型 | 用聚合数据回归各渠道贡献，不依赖个体追踪 |
| Incrementality / Lift | 增量实验 / 提升度 | 用对照组测"这笔钱不花会怎样"，唯一因果口径 |
| GeoLift / Geo Test | 地理实验 | 按城市/地区分组的增量实验 |
| Attribution Window | 归因窗口 | 点击/曝光后多长时间内发生的转化算数（如 7d click / 1d view） |
| View-Through Conversion | 曝光后转化（VTC） | 只看到没点击也转化，是否计入争议极大 |
| Click Injection | 点击注入 | 恶意 SDK 在安装完成前抢先发点击，劫持自然量归因 |
| Click Flooding / Spam | 点击洪水 | 海量伪造点击碰运气抢归因 |
| Self-Attributing Network (SAN) | 自归因网络 | Google/Meta/TikTok 自己报数，不接受第三方核查 |

### 5.7 联盟与套利

| 术语 | English | 通俗解释 |
|---|---|---|
| Affiliate | 联盟客 / 推广者 | 靠推广别人产品赚佣金的个人或公司 |
| Merchant / Advertiser | 商家 / 广告主 | 联盟里出佣金的一方 |
| Offer | 优惠 / 推广项目 | 联盟里可推广的具体商品或转化目标 |
| Payout | 佣金 / 派款 | 完成一个转化能拿到的钱 |
| EPC | Earnings Per Click，每点击收益 | Affiliate 侧衡量 Offer 质量的核心指标 |
| Sub ID / Click ID | 子渠道标识 | 追踪到具体流量来源的自定义参数 |
| Deep Link | 深度链接 | 直达 App 内某页或商品页的链接 |
| Cloaking | 伪装 | 给审核方和用户展示不同内容（**违规，仅作风险认知**） |
| Arbitrage | 套利 | 低价买流量、高价卖出转化收益，赚差价 |
| MFA | Made For AdSense | 专为 AdSense 做的低质高广告密度站（**违规，仅作风险认知**） |
| Native Ads Arbitrage | 信息流套利 | Taboola/Outbrain 买量 + 内容型落地页变现 |
| Domain Parking | 域名停放 | 未使用域名挂广告页赚分成 |
| RON | Run Of Network | 不定向、全网跑量，最便宜也最脏的流量 |
| Tier 1 / 2 / 3 | 地区分层 | T1：美英加澳等高价地区；T2/T3 依次递减 |

## 六、后续研究提问指引

### 6.1 五种典型提问方式（直接照抄模板）

**① 概念型** —— 想搞懂一个术语或机制
```
解释一下 <术语/机制>，我要：定义 + 英文原文 + 通俗解释 + 它在链路里的位置 + 国内海外差异
```

**② 现象型** —— 观察到一个业务/数据现象，想知道为什么
```
现象：<贴数据/截图/描述>
背景：<哪个产品/市场/时间>
帮我按业务层/产品层/技术层/商业化层拆解可能的原因，并给出验证方法
```

**③ 日志型** —— 有真实日志或报文，想读懂
```
下面是 <RTB bid request / 归因 postback / 广告日志>，逐字段解释含义，指出异常点和排查方向
<粘贴日志>
```

**④ 案例型** —— 看到一个玩法/竞品，想拆解
```
案例：<链接或描述>
帮我拆：商业模式（谁付钱谁赚钱）→ 产品链路 → 技术实现 → 毛利结构 → 风险与可持续性
```

**⑤ 对比型** —— 想做技术/平台选型判断
```
对比 <A> vs <B>：机制差异、适用场景、收益影响、接入成本、国内外主流选择
```

### 6.2 提问时给的上下文越全，答案越准

建议随手带上这几项（有则给，无则跳过）：

- **市场**：国内 / 海外（哪个国家/Tier）
- **端**：Web / Mobile Web / App（iOS / Android）/ CTV
- **角色**：我是买方（广告主/DSP）还是卖方（媒体/SSP）视角
- **阶段**：调研认知 / 方案设计 / 线上排查 / 复盘归因
- **约束**：时延、成本、合规、团队规模

### 6.3 我（研究助手）的回答承诺

1. **先定位再作答**：开头标注问题落在业务/产品/技术/商业化哪几层。
2. **术语必给英文**：`术语（English）= 一句话定义 + 行业通俗解释`，并提示是否易混。
3. **链路必画图**：涉及多方交互时用文字时序图或 Mermaid，标出数据流向与钱的流向。
4. **国内海外必对照**：默认两段，避免只讲一边。
5. **区分事实与推断**：明确标注「行业惯例」「某平台公开政策」「我的推断（待验证）」「已过期结论」。
6. **给可落盘产物**：结尾提供「可保存为 `目录/文件名.md`」，并给出该文档的建议结构，方便直接沉淀。
7. **给延伸追问**：每次结尾列 2~3 个值得继续挖的方向，形成研究链条。

### 6.4 建议的研究推进顺序

> 不强制，但按此顺序铺垫最少返工。

```
第 1 阶段  地基：01 行业总览 → 02 术语库 → 03 业务逻辑（拍卖与计费）
第 2 阶段  主干：05 技术架构（OpenRTB / DSP / 排序 / 出价）→ 04 产品形态
第 3 阶段  数据：06 定向数据 → 07 追踪与归因
第 4 阶段  生态：08 海外生态 → 14 国内市场 → 13 反作弊
第 5 阶段  玩法：09 Affiliate → 10 Arbitrage → 11 投放 → 12 变现
第 6 阶段  沉淀：15 案例复盘（持续）→ 16 前沿专题
```

## 七、协作规则

完整版见 [`00_研究方法与协作规范/协作规则.md`](./00_研究方法与协作规范/协作规则.md)。摘要：

1. 我提供**业务现象 / 日志 / 概念 / 案例**，你负责**拆解原理、架构、流程**。
2. 专业术语一律 **定义 + 英文原文 + 行业通俗解释**，并同步进 `02_核心术语与知识库/`。
3. **海外广告（Affiliate、Arbitrage、联盟网络、广告平台）重点讲解**，优先级高于国内。
4. 输出**结构化**，优先输出**可直接保存为本地 md 文件**的内容（含标题层级、表格、代码块）。
5. 广告问题优先按 **业务层 / 产品层 / 技术层 / 商业化层** 四层区分作答。
6. 每次研究结束明确给出**落盘路径**，我确认后由你写入对应目录。
7. 灰色地带（作弊、Cloaking、MFA）**只做防守方视角的原理与风险研究**，不产出可执行的规避方案。
