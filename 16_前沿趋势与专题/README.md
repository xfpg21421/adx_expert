## 写作要点

- **趋势类文档统一用五段结构**，缺段即视为未完成。这样多篇趋势文档才能横向比较：

```
1. 驱动因素      —— 是什么力量在推（政策 / 技术 / 商业动机），谁的利益在驱动
2. 当前成熟度    —— 概念期 / 试点期 / 规模期 / 退潮期；已落地的部分 vs 仍在 PPT 上的部分
3. 谁受益谁受损  —— 逐角色列出（广告主 / 平台 / 媒体 / DSP / SSP / Affiliate / 代理商 / 用户）
4. 3 年推演      —— 乐观 / 基准 / 悲观三条路径，各自需要什么前提条件才成立
5. 我的判断      —— 明确押注哪条路径，标 [推断]，并写清"什么信号出现就说明我错了"
```

- **区分事实、政策与推测**：已发布的政策标 `[政策]` + 版本与时点；厂商宣称标 `[宣称]`（未经独立验证）；
  自己的外推一律标 `[推断]`。三者混写是趋势类文档最常见的失效原因。
- **趋势要能被证伪**：每篇结尾列出 2~3 个可观察的领先指标（采纳率、支持该方案的平台数量、监管表态、头部客户案例），
  并登记到 `研究进度看板.md` 的失效复核清单，按季度复核。
- **跨目录专题的组织方式**：主文档放 `专题研究/`，按"背景→现状→各方立场→推演→对其他目录的影响"展开；
  受影响目录（如 `06`/`07`/`08`）只留一行链接指向主文档，不复制内容，避免同一结论多处漂移。
- 写"退潮"和"失败"与写"兴起"同等重要：DMP、Unified ID 早期方案、部分 Privacy Sandbox 组件都已边缘化，
  这类负面样本对判断新趋势的可信度最有价值。
