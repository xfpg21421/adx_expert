## 写作要点

- **所有优化手段必须落到 eCPM 公式的可乘因子上**，不能停在"接更多广告网络""提高填充"这类口号：

```
eCPM = 填充率 × 展示率 × 竞价密度 × 单次曝光价值 × 1000
     ↑ 每个因子对应一类优化手段
```

  写任何一篇优化文档时，开头先声明"本文影响的是哪几个因子、预期量级多少、代价是什么"。
- **区分两条技术路线**，几乎所有方案都要分栏写：

| 维度 | Web | App |
|---|---|---|
| 主流机制 | Header Bidding（Prebid.js / s2s） | 聚合 SDK（MAX / AdMob Mediation / TopOn / GroMore） |
| 竞价演进 | 从 Waterfall 到 in-page bidding | 从 Waterfall 到 in-app bidding（部分网络仍只支持 Waterfall） |
| 关键约束 | 页面性能、CLS、Ad Server（GAM）话语权 | SDK 体积与崩溃率、平台政策（ATT / Play 政策）、网络覆盖 |
| 身份与合规 | Cookie / TCF / Privacy Sandbox | IDFA / GAID / SKAN，隐私冲击更直接 |

- 写清各方案的**接入成本与收益量级**（人日 / 是否需改客户端 / 预期 eCPM 提升区间），否则无法做决策。
- 收益漏斗必须**先定口径再谈优化**：Ad Request 的分母是否含预加载、Fill 是否含 timeout、Render 与 Viewable 的差异，
  这三处口径不同会让"填充率"相差十几个百分点。
- 涉及 Google / Apple 政策与各平台抽成比例标 `[政策]` + 时点，并列入失效复核清单。
- 结论要带**代价**：任何提升 eCPM 的手段都写清它对留存、加载性能、用户体验或长期 LTV 的负面影响。
