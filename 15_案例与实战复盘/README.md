# 15_案例与实战复盘

> **本目录用途**：**沉淀层**。把真实的业务现象、日志、竞品观察，用统一模板拆成可复用的认知。
> 这是本项目区别于"读书笔记"的核心价值——这里的所有内容都来自真实观察，而非二手资料的整理。

**在全局中的位置**：反哺层。`01`~`14` 是自上而下的知识框架，本目录是自下而上的证据来源；
每篇案例的「认知更新」会回流去修订对应目录的结论，「待验证」会进入 `00_研究方法与协作规范/研究进度看板.md` 的问题池。

---

## 文档清单

- [ ] `案例索引.md` —— 全量案例表格索引：日期 / 案例名 / 类型 / 市场 / 一句话结论 / 链接
- [ ] `复盘方法论.md` —— 复盘的四个层次（现象→机制→模型→行动）；如何避免事后归因偏差；什么时候值得写复盘
- [ ] `业务现象拆解/` —— 指标异动、业务现象的诊断记录，命名 `YYYYMMDD_现象名.md`
- [ ] `日志与数据诊断/` —— RTB 报文、postback、埋点日志的分析记录，命名 `YYYYMMDD_日志类型_问题.md`
- [ ] `竞品与产品拆解/` —— 平台、工具、产品的能力拆解，命名 `YYYYMMDD_产品名.md`

**建议顺序**：复盘方法论 → 案例索引（先把方法定死、索引建好，之后由真实问题驱动逐篇增补，不追求凑数）

## 写作要点

- **一律套用模板**：所有案例文件使用 [`../00_研究方法与协作规范/案例拆解模板.md`](../00_研究方法与协作规范/案例拆解模板.md) 中对应的四类模板
  （商业案例 / 业务现象诊断 / 竞品拆解 / 日志分析），不要自创结构——结构不统一就无法横向比较与检索。
- **文件命名带日期**：`YYYYMMDD_案例名.md`（日期为事件发生或复盘当天）。命名即时间线，禁止用"最新""修订版"这类无日期后缀。
- **每篇结尾必须有两节**，且缺一不可：
  - 「认知更新」：这个案例让我改变了哪条既有判断（要写清**改前 vs 改后**，以及影响哪个目录的哪篇文档）；
  - 「待验证」：还没被证据支撑的推测，标 `[推断]`，写清验证方式与所需数据。
  两节内容同步登记到 [`../00_研究方法与协作规范/研究进度看板.md`](../00_研究方法与协作规范/研究进度看板.md) 的认知更新日志与待研究问题池。
- **二选一归属规则**：偏**玩法**的案例（怎么投、怎么变现、怎么套利）放对应业务目录的案例子目录
  （`03/商业化案例/`、`09/联盟案例拆解/`、`10/套利案例拆解/`、`12/变现案例拆解/`、`13/反作弊案例/`）；
  偏**诊断**的案例（指标为什么异动、日志为什么对不上、产品能力如何）放本目录。同一事件只写一处，另一处留链接。
- **写事实与证据，不写立场**：数据带口径与时点，截图与原始日志片段脱敏后放 `99_参考资料与归档/图片与附件/`；
  结论分「已证实 / 待验证 / 已推翻」三态，被推翻的旧结论保留并标注，不删改历史。
- 什么时候值得写：出现了**与预期不符**的现象、或得到一个**无法从公开资料推出**的数字。两者都不满足时不必成文。
